Three Agentic Architecture Approaches

Pick the one that fits best — I'll explain my recommendation below

A

Pure ReAct Loop

LLM reasons and acts turn-by-turn, sees each tool result before deciding next step

LLM: Thought: I need to geocode the location
LLM: Action: geocode("Neukölln Rathaus")
→ Python runs tool → returns coords
LLM: Observation: 52.4823, 13.4352
LLM: Thought: Now I'll create a 500m buffer
LLM: Action: create_buffer(coords, 500)
→ Python runs tool → returns polygon
LLM: Thought: Now query for playgrounds
LLM: Action: query_db("playgrounds in buffer")
LLM: Final Answer: GeoJSON + "14 found"

Pros

  • Most adaptive — reacts to each result
  • Can handle surprises mid-query
  • Transparent reasoning

Cons

  • Many LLM round-trips (slow, expensive)
  • Can loop or get stuck
  • Harder to stream predictable progress
B

Plan-then-Execute ⭐ Recommended

One LLM call creates a step plan; Python executes each step sequentially, passing results forward

LLM (1 call) Plans all steps upfront:
[geocode → buffer → query_db → format_geojson] Python Streams progress: "Step 1/4: Geocoding..." ✓
Feeds each result as input to next step LLM (1 call) Synthesizes final GeoJSON answer from all results

Pros

  • Only 2 LLM calls (fast & cheap)
  • Predictable progress — great for streaming
  • Results chain naturally between steps
  • Easy to debug each step

Cons

  • Plan is fixed — can't replan mid-execution
  • If step 2 fails, must restart
C

Adaptive Plan (Plan + Replan)

Creates a plan, but LLM can revise it after each step based on results

After each tool result, LLM decides:
{ "continue": true, "next_step": "buffer" } { "replan": true, "reason": "location not found, try alternate name" }
LLM calls: 2 (happy path) to N (if replanning needed)

Pros

  • Handles failures gracefully
  • Can try alternate strategies
  • Best reliability

Cons

  • Most complex to build
  • Variable number of LLM calls
  • Harder to stream predictable progress
My recommendation: Option B (Plan-then-Execute)
It gives you predictable streaming (user sees each step tick by), only 2 LLM calls per query (planner + synthesizer), and results naturally flow between steps — the geocoded coordinate feeds directly into the buffer, which feeds into the SQL query. We can add retry logic per-step in Python without needing extra LLM calls. Option C's replanning can be added later as an enhancement once the core is solid.
