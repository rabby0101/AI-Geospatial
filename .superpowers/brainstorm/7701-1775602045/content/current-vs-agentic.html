Current Flow vs. Agentic Flow

For the query: "How many playgrounds are within 500m of the Neukölln Rathaus?"

❌ Current Flow (Breaks Often)

One big LLM call tries to solve everything at once

User
"How many playgrounds within 500m of Neukölln Rathaus?"
↓
LLM — Single Megacall
"Generate SQL that geocodes Neukölln Rathaus, creates a 500m buffer, and counts playgrounds in it — all at once"
↓
PostGIS
Runs generated SQL (often wrong — hallucinated coordinates, bad geometry operations)
⚠ Fails or returns wrong results
Why it breaks:
  • LLM must guess coordinates for "Neukölln Rathaus"
  • Buffer + count in one SQL is complex & hallucination-prone
  • No intermediate error recovery
  • If one part fails, everything fails

✅ Agentic Flow (Proposed)

LLM orchestrates specialized tools, step by step

User
"How many playgrounds within 500m of Neukölln Rathaus?"
↓
Agent — Plans Steps
"I'll geocode the location first, then buffer, then count."
↓
Tool Call 1 — geocode_location
"Neukölln Rathaus" → 52.4823°N, 13.4352°E
↓
Tool Call 2 — create_buffer
52.4823°N, 13.4352°E + 500m → POLYGON(...)
↓
Tool Call 3 — query_database
SELECT count(*) FROM playgrounds WHERE ST_Within(geom, buffer) → 14
↓
Agent — Final Answer
"There are 14 playgrounds within 500m of Neukölln Rathaus."
Why it works better:
  • Each tool does one thing reliably
  • Real geocoded coordinates, not LLM guesses
  • Agent can recover from tool errors
  • You see exactly what happened at each step
