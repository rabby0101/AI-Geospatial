Design — Section 2: New Tools

12 new tools across your 4 selected directions — select any you'd remove or change

A · New Geometries from Existing Data

generate_voronoi(table, id_col)
Voronoi polygons around input points. Each polygon = the area closest to that point.
"Generate hospital coverage zones for Berlin"
generate_hexgrid(bbox, cell_size_m)
Hexagonal grid covering any bounding box. Useful base layer for density and scoring.
"Create a 500m hex grid over Mitte"
generate_convex_hull(table)
Minimum bounding polygon around a set of features.
"What area do all the schools cover?"
generate_corridor(route_geom, width_m)
Buffered corridor along a road or route — for planning pedestrian zones, bike lanes, etc.
"Generate a 200m corridor along Unter den Linden"

B · Suitability & Site Selection

site_suitability(criteria)
Multi-criteria scoring on a hex grid. Each criterion: table + distance weight + direction (near/far).
"Find best 5 locations for a new clinic, near transport, far from existing clinics"
coverage_gaps(service_table, radius_m)
Finds areas NOT within radius of any service. Returns underserved polygons.
"Show areas more than 1km from any pharmacy"

C · Derived Analytical Surfaces

kernel_density(table, bandwidth_m, grid_size_m)
Point density surface as a scored grid. Reveals clusters and sparse zones.
"Show density of restaurants across Berlin"
equity_gap_analysis(service_table, district_table)
Compares service counts per district, flags statistically underserved ones. Built for NGO equity reporting.
"Which districts have the worst school-to-population ratio?"
accessibility_surface(target_table, mode, max_min)
Grid of travel times to nearest target feature using Valhalla isochrones.
"Show walking time to nearest hospital for every part of Berlin"

D · Scenario Planning & What-If

add_hypothetical(layer_name, geometry, properties)
Adds a hypothetical point/polygon to a named scenario layer in PostGIS.
"Add a hypothetical hospital at Tempelhof"
compare_scenarios(baseline_layer, scenario_layer)
Runs coverage_gaps on both layers and returns a diff — what improved, what didn't.
"How does adding that hospital change coverage gaps?"

All generated layers are saved to temp_layers schema with a semantic name so the agent can reference them in follow-up queries.
