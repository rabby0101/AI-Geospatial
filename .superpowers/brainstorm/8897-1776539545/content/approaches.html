How should we expand the agent's capabilities?

Three approaches — each covers all 4 directions but with different depth and architecture

A

Toolbox Expansion Low risk

Add ~10 new tools directly to the existing TOOL_REGISTRY in agent_tools.py. Each tool is self-contained and the agent picks which to call.

Pros

  • Follows existing patterns exactly
  • Fast to implement
  • Agent already knows how to chain tools

Cons

  • Generated features don't persist between queries
  • No "build on previous result" capability

New tools: voronoi_diagram, convex_hull, kernel_density, site_suitability, catchment_area, hexagonal_grid, corridor_analysis

B

Spatial Analysis Module + Persistent Layers Recommended

Build a dedicated spatial_generator.py module with Shapely-heavy operations. Generated features get saved back into PostGIS as named layers (reusing the existing temp_layers pattern) and can be referenced in follow-up queries.

Pros

  • Generated layers persist and can be queried again
  • "Analyze the voronoi zones I just created" works
  • Urban planners can revisit and compare scenarios
  • Reuses existing temp_layers infrastructure

Cons

  • More code than option A
  • Needs layer naming / management logic

New tools: Everything in A + save_generated_layer, compare_scenarios, equity_gap_analysis

C

Generative Workspace (Session Canvas) Most powerful

A session-based workspace where generated features accumulate and the agent has full memory of what was created. Users can layer analyses: generate Voronoi zones → score them → run what-if scenarios → compare.

Pros

  • True scenario planning workflow
  • Most impactful for urban planners
  • Agent can reference "the coverage gaps from earlier"

Cons

  • Significant architecture changes needed
  • Session state management complexity
  • Higher implementation risk

New tools: Everything in B + session workspace manager, layer compositor, multi-scenario comparator

💡 My recommendation: B — it gives you persistence and composability without the complexity of full session state. You can always evolve toward C later.
